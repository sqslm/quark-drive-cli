# PotPlayer 0.10.1：诊断启动修复与模块解耦

## 问题与边界

本机复现：旧 `accounts.json` 使用 `{current, accounts: [...]}`，0.10.0 只接受带版本号的账号字典。服务构造时的异常导致打开诊断也触发 PyInstaller 未处理异常。

- 账号存储：识别已确认的旧格式，先保存私有备份，再迁移全部凭证和当前选择。原账号专属 `library-<id>.json` 保持原路径及归属；不猜测其它文件的账号归属，不覆盖未知格式。
- 账号文件不可用时，账号模块明确报错且拒绝写入；服务和本地诊断仍可启动。
- `status_gui.py` 只拥有播放与传输诊断；`accounts_gui.py` 拥有账号、登录与容量；`highlights_gui.py` 拥有精彩标记和播放器绑定。
- `management_gui.py` 只承载三个标签页。各页面有独立 HTTP 客户端、队列和工作线程；共用的仅是本地传输、生命周期与纯格式化函数。
- 诊断读取 `/v1/diagnostics`；账号读取 `/v1/accounts`；精彩标记读取 `/v1/bookmarks/state`。诊断接口不承载账号列表、登录流程或精彩标记请求。
- 本地观察接口不等待账号云端操作锁，通过同一不可变上下文读取播放资源，保留切换账号的写入校验。

## 验收

1. 用相同旧格式复现失败，再确认迁移保留两个登录、当前账号、原记录路径和备份。
2. 损坏账号文件时，诊断和标记上下文正常响应，账号操作报错且原文件不变。
3. 慢账号请求不阻塞诊断或精彩标记上下文；三个页面独立持有状态和请求。
4. 回归现有播放、账号隔离及精彩标记测试，实际打开三个页面与标记窗口。
5. 生成 0.10.1 安装包，验证打包启动、旧格式迁移与异常账号场景，再提交。
